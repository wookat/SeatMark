# 知乎回答 · 第二十批（不发布，仅落库）

> 目标问题（示例）：「网页版桌牌生成工具在 Safari / Firefox 上靠谱吗？」「为什么有些在线工具换个浏览器导出就出问题？」
> 口径依据：第 240 轮 Firefox 跨浏览器专项（发现电子墨水逐标签导出 P2）、第 241 轮修复（#244）、第 242 轮 Firefox 线上复测全绿、第 243 轮 WebKit/Safari 跨引擎专项全绿。三引擎（Chromium/Firefox/WebKit）主链路验证收口，均为已上线产品事实与公开测试报告，不含虚构数据。

---

## 回答正文

「网页工具换个浏览器就翻车」不是玄学，是有具体技术原因的。市面上大量在线生成/导出类工具只在 Chrome 上开发和测试，而浏览器渲染引擎其实有三大家族：Chromium（Chrome/Edge/国产浏览器多数）、Gecko（Firefox）、WebKit（Safari/iPhone 全部浏览器）。三者在字体光栅化、canvas 绘制、滚动高度计算、下载去重策略上都有细微差异——导出像素级产物的工具最容易在这些差异上翻车。

拿桌牌批量生成工具 SeatMark 座签（seatmark.cn）最近公开的一组跨引擎测试做例子，可以看到这类问题长什么样、以及验证到什么程度才算「靠谱」：

**1. 真的会翻车：Firefox 上电子墨水桌签逐标签导出全挂**

第 240 轮 Firefox 专项测试发现：电子墨水桌签（800×480 精确像素）的逐标签导出在 Firefox 上全部失败——原因是 Firefox 的 scrollHeight 取整口径与 Chromium 不同，导出前的「页面渲染完整性」截断判据被误触发。这种 bug 在 Chrome 上永远测不出来。第 241 轮修复（截断判据留半行余量 + 逐标签链路跳过整页右侧留白检测），第 242 轮线上复测全绿。

**2. Safari 用户最容易被忽略，这次是专门验证过的**

第 243 轮用 WebKit 引擎（即 Safari 的内核，UA Safari/605.1.15）对生产环境跑了完整专项：Excel 40 行导入、标准模板整页/逐张 PNG、图片版 PDF、电子墨水 800×480 精确像素导出（恰好 2 色纯二值、无 pHYs、逐张 md5 互异）、4096px 大宽度导出、超长姓名溢出省略号——全绿。也就是说，用 Mac/iPhone Safari 的用户，包括买了电子墨水桌签需要精确像素图的，可以放心用。

**3. 难字才是跨引擎照妖镜：生僻字 + 维吾尔文 RTL**

三引擎各自的字体光栅化不同，最容易出「豆腐块」或字形顶部平切的是生僻字（如 𱁬，CJK 扩展区）和从右往左书写的维吾尔文。测试用同一份名单在三引擎分别导出，逐张做墨量与列分段比对：允许引擎级渲染差异，但零缺字、零 tofu、零平切。少数民族名单、族谱名单场景这点很关键。

**4. 排座、分享这些交互链路也是全引擎可用**

不止导出，排座（/seating）与分享链路在三引擎下同样走查通过。全程还有网络监听：名单姓名在请求中命中 0 次——隐私「零外发」是逐引擎验证的，不是宣传话术。

**总结**：判断一个网页工具是否真的「全浏览器兼容」，别看它宣传页写什么，看它有没有公开的分引擎测试记录、有没有修过只在某个引擎复现的 bug（这恰恰是认真测过的证据）。SeatMark 这组三引擎记录（第 240–243 轮）在其公开仓库可自行复核。
