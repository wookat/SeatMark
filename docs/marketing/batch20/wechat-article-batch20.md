## 标题

《「请使用 Chrome 打开」是一种偷懒：一个桌牌工具的三引擎真机验证记》

## 正文

网页工具的宣传页上很少写一句话：「我们只在 Chrome 上测试过。」但很多工具的真实情况就是如此——直到某个用 Safari 的用户导出文件失败，才发现所谓「网页版，打开即用」是有前提的。

浏览器世界其实只有三大渲染引擎：Chromium（Chrome、Edge 及绝大多数国产浏览器）、Gecko（Firefox）、WebKit（Safari，以及 iPhone 上的所有浏览器——iOS 上连 Chrome 用的也是 WebKit 内核）。三者在字体光栅化、canvas 绘制、滚动高度取整、下载去重策略上都存在细微差异。对于要输出像素级产物的批量生成工具，这些差异就是事故来源。

SeatMark 座签（seatmark.cn）最近用四轮测试（第 240–243 轮）把三个引擎逐一真机验证了一遍。这个过程值得讲，因为它展示了「全浏览器兼容」四个字应该怎么兑现。

### 一、先承认：Firefox 上真的翻过车

第 240 轮 Firefox 专项测试发现了一个 Chrome 上永远测不出来的 bug：电子墨水桌签（800×480 精确像素）的逐标签导出在 Firefox 上全部失败。根因是 Firefox 的 scrollHeight 取整口径与 Chromium 不同，导出前的「页面渲染完整性」校验被误触发，把正常页面判成了渲染不完整。

第 241 轮修复：截断判据留出半行余量，逐标签链路跳过整页右侧留白检测。第 242 轮线上复测全绿。**敢公开「发现 bug → 修复 → 复测」完整记录的工具，比宣称「从未出过问题」的工具可信得多。**

### 二、Safari：最容易被忽略的三分之一

Mac 办公环境、以及所有 iPhone/iPad 用户，用的都是 WebKit 引擎。第 243 轮用 WebKit（UA Safari/605.1.15）对生产环境跑了完整专项：

- Excel 40 行名单导入、字段映射——通过；
- 标准模板整页 PNG（2481×3509）、逐张 PNG 40 张、图片版 PDF——全部落盘并逐像素核验非空白；
- 电子墨水 800×480 精确像素导出——恰好 800×480、纯二值两色、无多余 pHYs 元数据、逐张 md5 互异；
- 4096px 大宽度自定义导出——120 秒内完成，40 张 4096×2458；
- 60 字超长姓名——溢出省略号正常，无叠压。

买了电子墨水桌签设备、手头只有 Mac 的用户，从此不需要为了导一张精确像素图去装 Chrome。

### 三、难字是照妖镜：生僻字与维吾尔文

三引擎字体渲染差异最容易暴露在两类文本上：CJK 扩展区生僻字（如 𱁬）和从右往左书写的维吾尔文。测试用同一份名单在三引擎分别导出，对产物逐张做墨量与列分段比对——允许引擎级的渲染风格差异，但零缺字、零豆腐块、零字形顶部平切。对少数民族名单、族谱桌牌这类场景，这是能不能用的分水岭。

### 四、不止导出：排座、分享、隐私逐引擎走查

排座（/seating）与分享链路在三引擎下同样走查通过。更重要的是，每一轮测试都挂着全程网络监听：名单中的姓名字符串在所有网络请求中命中 0 次——「名单不出浏览器」的隐私承诺，是在三个引擎上分别验证过的。

### 写在最后

「全浏览器兼容」不该是宣传页上的一个图标，而应该是一组可复核的测试记录。SeatMark 的三引擎验证记录（第 240–243 轮，含发现并修复的 Firefox bug）全部公开在其代码仓库中。下次再看到「请使用 Chrome 打开」的提示，你可以知道：那不是技术限制，是没测。
