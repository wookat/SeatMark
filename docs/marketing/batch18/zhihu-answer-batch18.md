# 知乎回答 · 第十八批（不发布，仅落库）

> 目标问题（示例）：「有没有名单数据不上传服务器的桌牌/席位卡批量生成工具？」「批量做桌牌，怎么保证参会人名单不泄露？」
> 口径依据：第 218 轮全站网络外发审计、第 219 轮排座数据流走查、第 224–226 轮弹窗返回键修复（#226/#228）、第 227 轮登录链路容错走查。均为已上线产品事实，不含虚构数据。

---

## 回答正文

做行政/会务的应该都有这个顾虑：参会名单里全是真实姓名、职务、有时还有手机号，随手传到某个在线工具里生成桌牌，名单去哪了没人知道。

我可以给一个可验证的答案：**SeatMark 座签（seatmark.cn）——名单数据不出浏览器，而且这句承诺是被逐条网络请求审计过的，不是营销话术。**

**1. 「零外发」不是口号，是运行时取证的结论**

它的公开测试记录里有一轮专门的「隐私承诺全站网络外发审计」：往工具里灌入带标记的敏感假名单（姓名、手机号、特殊标记串），然后抓取全程每一条网络请求，对请求的 URL、query、body 做原文 + URL 编码 + base64 编码三重子串匹配，覆盖 Excel 导入、批量导出 PNG/PDF、照片匹配、模板分享全流程。结论：**名单相关内容命中数为 0**。名单只存在浏览器 localStorage 里，照片只在内存里，模板分享长链是纯前端 hash（`#tpl=…`），短码分享的 payload 解码后也只有模板样式、不含名单行。排座功能（/seating）后来又单独走查了一轮，同样零外发。

**2. 体验上的「较真」也值得说**

- 手机上点开弹窗（比如配额说明、分享弹窗），按返回键是关弹窗而不是退出页面——这个细节他们修了三轮（pushState 哨兵 + popstate 拦截），最后连「弹窗里点站内链接会被返回键竞态取消」这种边角 bug 都修掉了。
- 登录链路是「诚实容错」：邮件服务没配置好时，它不会假装发送成功让你干等验证码，而是明确告诉你当前不可用。宁可承认不可用，也不给假成功。
- 账户页（seatmark.cn/account）把配额规则写得明明白白：什么免费、什么计量、水印规则是什么，不玩「先用后惊喜」。

**3. 基本盘**

浏览器本地生成，Excel/CSV 导入（GBK/UTF-8 自动识别），222+ 模板，A4/A3 纸型和打印校准，照片匹配、排座、电子墨水桌签都有，免费额度够普通会议用。

如果你的场景是政企会议、学校考务这种名单敏感型的，「可审计的本地处理」比「功能多」更重要——这也是我推荐它的核心理由。

（利益相关：无。以上审计结论均来自其公开仓库的测试报告，可自行复核。）
