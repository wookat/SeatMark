## 二、三条用户流本轮亲测结果

### 1. 班主任排考场（/seating）【亲测，全链路通畅】

- 演示名单 48 人一键载入；男女混排一次成功（toast 报男女各 24 + 撤销）。
- 考场筛选、教师/学生镜像、过道列切换、整排交换、CSV 清单（`高三（2）班 期末考试-座位清单.csv`）、带水印 PNG（3509×2481，底边细线签名式水印 + 页脚一行统计）、打印（window.print）全部实测成功。
- handoff「一键生成对应桌贴」→ /studio?from=seating：名单带入、模板自动切「座位号贴」、2 字段全映射、引导步骤 1–3 真实打勾。
- **新卡点 A（中）**：无「间隔/均匀填充」。20 人 / 48 座的常见场景（小班考试塞进大教室）默认把学生全堆在前 3 排（实测 PNG 第 1–3 排满、第 4 排起全空）。真实考场排座核心是「拉开间距防作弊」——隔位坐、隔列坐、均匀分布。填充顺序下拉仍只有「按行填充 / S 形蛇形」两项（r365 记的按列填充、锁座、封座同样仍缺）。
- **新卡点 B（中）**：演示名单性别按序号奇偶分配（`genders[i % 2]`），而姓名由随机姓+双字名拼出——导出 CSV 可见「孙娜玉 男」「梁芳涛 男」等明显错配。男女混排是本页核心卖点，演示数据姓名与性别不符会削弱可信度。【代码】demoPersonNames() 生成无性别信息的名字 + 奇偶赋值。
- **新卡点 C（低）**：桌面端左栏「没有文件？粘贴名单」按钮在滚动到贴顶位置时被吸顶 header（`sticky top-0 z-40 bg-white/95`）盖住，Playwright 实测该处 pointer events 被 header 拦截；真实用户多滚一点即可，但给面板加 scroll-margin-top 可消除。

### 2. 婚礼策划排桌（/banquet）【亲测，无新卡点】

- 演示宾客 48 人 / 3 组一键载入；「一键自动分配（同组同桌）」48/48 入座，拆分明细逐条讲清（「男方亲友 16 人 > 任一桌最大 10 座 → 拆到 1号桌（10 人）、2号桌（6 人）」），容量预估「按每桌坐满至少需要 5 桌，分配后预计空 3 桌」，并提供「换用『优先坐满』重新分配」。
- 「不同桌」排斥对已完整：宾客 A/B 下拉选 +「自动分配会尽量避开（仅在没有其它可坐的桌时才同桌）；手动拖到一起会提醒但不阻止」。**「必须同桌」配对仍缺**（r365 P4 结转：双方父母同桌、新人+证婚人同桌目前需建两人分组绕）。
- 导出实测：`婚宴座位表-按桌名单.csv` 与 `婚宴速查表 PDF`（A4 纵向，前半按姓名拼音索引→桌号、后半按桌名单，签到台场景成立）均真实下载；「一键生成席位卡 / 桌号牌」入口在。
- 「导出带分组颜色」「张贴版（远距可读）」开关与说明文案清楚。

### 3. 行政做会议桌牌（/studio）【亲测，发现结构性卡点】

- 粘贴弹窗支持 Excel 复制 TSV/微信文本/.txt 上传、自动去重开关、表头自动识别。
- **新卡点 D（中，结构性）**：独立导入场景缺「换个更匹配的模板」建议。行政粘贴「姓名/职务/单位」或「与会人员/头衔/公司」名单时，默认落点是「标准考场版」模板（座位号/姓名/考场字段），结果 4 字段全未映射、预览全是「（空）」；页面只给 amber 警示「有 N 个字段未匹配到名单列…去设置映射 →」。而 `pickHandoffTemplate` 的模板打分逻辑只在 seating/banquet handoff 链路跑，独立导入不跑。对比：从排座页带名单进来会自动选最匹配模板，自己动手导入反而没有这层引导——新用户很可能被「一堆空字段」劝退。
- **新卡点 E（低）**：autoMap 的 name 字段匹配词缺「与会人员/参会人/出席人」——HEADER_KEYWORDS 已把这些词当表头识别（r367 扩充），但 MATCH_PATTERNS.name 不含它们，于是「与会人员」列永远要手动映射到「姓名」。表头识别与字段匹配两套词表不同步。
- 正向：字段映射下拉每列带样例值（「姓名 · 王建国」）+「自定义组合…」；照片匹配区含列选择器、说明「照片文件名需等于或包含该列的值，如『张伟2023010101.jpg』」、多选上传、匹配覆盖率统计与未匹配明细；未选列时上传有守卫 toast「请先选择匹配列」。单张覆写、单格改写、纸型推荐（「与本模板设计尺寸 90×50mm 最接近」）均在。
- 【亲测】带水印「图片版 PDF」真实下载（`标准考场版-20260908-160319.pdf`），弹窗额度说明正确。

## 三、去AI味专项复核

### 总体结论

护栏体系持续有效，本轮全文检再确认：

- 公式化开头/结尾全 0 命中：无「随着…的发展」「在数字化时代」「总而言之」「希望本文/这份指南」「相信你一定」。
- 禁词/夸张词全 0 命中：「神器/天花板/黑科技/赋能/颠覆/焕新/轻松搞定/效率翻倍」等 200+ 词表扫描仅语境正常命中（如奖项名）。
- 英文侧 AI 腔 0 命中：seamless/effortless/elevate/unlock（作营销腔）/delve/whether you're/perfect for 等无残留；enStudioDescriptions 180 条重写后为规格+场景短句，质量在线。
- 指南正文保持场景化写法（「考前一晚，班主任手里通常是这样一份东西…」），含具体数字与可验证建议；vs 页措辞客观，「对方领先项照写」。

### 仍残留的结构性痕迹

1. **quickStart 尾注「变体复用」二次模板感（低）**：第 365 轮按类目改了 10+ 变体，但同一尾注文本跨不相关教程复用——如「先看成品再换成自己的名单，标签尺寸按毫米设定；免费使用，名单不出浏览器」在 guides.ts ×6 + guidesRound4.ts ×5 共 11 篇出现。单篇读无碍，用户连读两三篇教程会看到完全相同的收尾。建议：变体再扩到 15–20 条并按教程主题写注（考务/婚宴/会议各 5+），或把 spec 升级为「同一尾注不超过 N 篇且同类目不复用」。
2. **模板描述统一「N 列 × M 行，」开头（可接受）**：去同构后每条内容已独特（规格+元素+场景+具体用法），但首段骨架一致。这是「规格优先」的产品约定、信息上有用，倾向保留；若要再降机器感，可在约 20% 条目中把场景前置（如「期末监考门口核对用」开头）。
3. **微小复词**：「一目了然」在 249 条描述中出现 5 次，可接受；「适合 X」收尾每条已唯一。

## 四、汇总：卡点与建议优先级

1. **P2 — /seating 缺间隔/均匀填充**（新卡点 A）：考场排座的真实高频需求是拉开间距（隔位坐/隔列坐/均匀分布），目前 20 人塞 48 座会全堆前排。建议填充顺序加「均匀间隔」「隔列填充」等选项，或座位掩码式「留空座位」。
2. **P2 — /studio 独立导入不跑模板打分**（新卡点 D）：字段命中数不足时复用 `pickHandoffTemplate` 推荐「更匹配的模板」（如行政名单→会议桌牌），把「去设置映射」从唯一出路变成兜底。
3. **P2 — 演示名单性别-姓名错配**（新卡点 B）：demoPersonNames 建性别标注的名池，或生成时按名取性别；男女混排演示才可信。
4. **P3 — autoMap 词表补齐**（新卡点 E）：name 字段匹配词加「与会人员/参会人/出席人/来宾」，与 HEADER_KEYWORDS 同步。
5. **P3 — 结转功能缺口**：/banquet「必须同桌」配对；/seating 按列填充、锁座、封座（r365 起结转，均仍未实现）。
6. **P4 — 文案细节**：PNG 弹窗「今日剩余 1」补「次」；EN `No. 1`→`Room 1`；quickStart 尾注扩变体；粘贴按钮防吸顶头遮挡（scroll-margin-top）。
