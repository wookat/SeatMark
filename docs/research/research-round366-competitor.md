## 一、本轮相对第 364 轮的增量发现

### 1. SeatLogic 定价与产品细节首次拿到（【直查】seatlogic.app）

- 定价：Free ≤100 宾客（含基础关系图、优化器 Essential 版、云同步）；Essential **$399.99/年**（≤250 宾客、导出、1 项目）；Professional **$999.99/年**（不限宾客/项目、本地工程文件、**实时多人协作**、自定义品牌）。
- 功能细项：关系图（couple/family/friend/avoid 四色连线 + 分组彩色气泡）、CSV/Excel/粘贴导入、**50+ 步撤销重做**、自动保存、键盘快捷键、宣称可离线、CSV 导出。
- 卖点叙事直接打痛点：「You move one guest and three tables break」「divorced in-laws」——把「谁不能坐一起」做成首页第一屏。

### 2. wedgenerator.com  seating-chart-maker（【亲测】，本轮新发现的强参照物）

- 全部浏览器本地、免注册免费、localStorage 持久化（`wedgenerator.seating-chart.v1`）。
- **亲测实证**：粘贴 12 人名单 →「Import 12 guests」→「Auto-arrange by tag」→ 12 seated / 0 unassigned / 2×Round10 桌，一次成功；支持 Upload CSV/Excel 与 Download sample CSV。
- **Copy share URL 亲测实证**：整张图表（宾客+桌+冲突对+分配）压缩进 URL `#chart=` fragment，打开链接即在对方浏览器还原快照——**这正是 SeatMark 已有的「模板 hash 分享」模式被对手用在排座图上**，直接验证了 G7 机会的可行性与零后端路线。
- 冲突对「Don't-seat-together」为软警告（同桌则红框+顶部计数），不阻止——与 SeatMark「不同桌」软约束同档。
- Floor plan 视图为只读 SVG 几何图（圆桌/长桌+周边姓名），供场地/婚庆查看。
- 附带「Find-Your-Seat sign」生成器（宾客按姓氏字母速查的迎宾牌）——对应 SeatMark 已有的 A4 速查表方向。

### 3. placecard.us 功能升级（【直查】/zh 页）

- 第 364 轮记录的 G4（Google 表格导入）确认仍在；**新增看到**：「支持餐食信息——从表格读取餐食选择自动显示在座位卡上」（G8 已被对手完整实现）、100+ 模板、Avery 5302 与 6 格卡纸版式、云端保存自定义模板、宣称「50万+ 已制作座位卡 / 5万+ 已服务活动」。
- 隐私话术与 SeatMark 同构：「Excel/CSV 浏览器本地读取；Google 表格导入采用临时中转，默认不保存名单」——但 Google 表格导入本身即一次出域传输，SeatMark 的「零上传」叙事仍更彻底。

### 4. 「扫码查座」是一个已成立的中文品类（【二手】多家，【直查】yunhuizhu.cn 首页文案）

- 婚礼纪 App：婚宴座位表 → 生成**长期有效的动态查座二维码**，宾客微信扫码查自己桌号与邻座，可转发微信群（【二手】教程文）。
- 云会助 yunhuizhu.cn：扫码查座位/扫码选座位/付费报名一站式，微信扫码免装 App，基础功能免费（【直查】首页）。
- 趣座位 vq18.cn：30 套模板，扫码后输姓名/电话查桌号房号，叠加签到+大屏抽奖（【二手】）。
- PlanSeats（dev.to 用户帖，2026-08）：宾客现场扫码找座 + 策划师实时协作（【二手】用户自述）。
- **判断**：该品类全部是「名单上云 + 服务端查询」架构，与 SeatMark 零上传铁律正面冲突；可参考的价值点是「宾客自助查座」这个需求本身，而非其架构。

## 二、用户真实讨论 → 未满足需求（标注证据）

1. **「谁不能坐一起」仍是排座第一痛点，且已被多家做成首页第一屏**：SeatLogic（divorced in-laws/falling-out friend groups）、Seatify（keep-apart rules）、wedgenerator（conflict flag）、SeatCanvas 博客（divorced parents 专题 16 分钟长文）——四家独立产品都把冲突管理当核心卖点，需求成立【二手×4】。对应 SeatMark：宴会视图已有「不同桌」软约束，**硬约束/自动分配保证拆开仍缺**。
2. **名单最后一刻变更是常态，「改动成本」是工具价值的核心度量**：wedgenerator「flex table 应对迟到 RSVP」、码匠「名单再改也只需半分钟」、SeatCanvas「re-export in minutes when something changes」【二手】。→ SeatMark 增量改名单已有雏形（R364 代码核实 SeatingView 行 291），可继续打磨为卖点。
3. **电子表格版本混乱是协作诉求的根源**：dev.to 用户自述「my mom suggested a different arrangement, my fiancé disagreed, we were all working from different versions of the same file」【二手】。→ 无后端约束下的最优解 = 排座 hash 快照分享（wedgenerator 已实证模式）。
4. **宾客自助查座（扫码/输姓名）是中文会务婚庆的成熟需求**：婚礼纪动态查座码、云会助、趣座位、PlanSeats QR【二手】。→ 与零上传铁律冲突；可行变体见机会点 O6。
5. **打印落纸环节仍是高发翻车点**：多篇教程强调「先打测试页量尺寸」「手动双面逆页序易错位」「不同打印机边距处理有差异」【二手 codechina/tsight 教程】。→ 工具内「先试打一页 + 校准指引」是低成本高感知改进。
6. **实体桌牌市场反向提示结构需求**：淘宝定制桌卡流行「三面立柱式（自稳）+ 正面桌号/反面手写姓名或印菜单、8 张起订」【二手 淘宝百科】。→ 印证 G2 多折叠结构+正反面独立内容方向；「背面留白可手写」是可新增的模板细节。
7. **Excel/Word 邮件合并教程持续高产**（2025–2026 年仍有多篇新教程），说明 WPS 路径仍是非专业用户默认方案，其 8–10 步流程、手工垂直翻转、无逐页网格预览的痛点未变【二手】。

## 四、机会点（按「投入小 / 差异大 / 不违反铁律」排序）

1. **排座 hash 快照分享**（G7）：复用模板 hash 管线把 /banquet、/seating 整图编码进链接；wedgenerator 已实证零后端可行性，且是回应「电子表格版本混乱」痛点的差异化武器。全部本地、不违隐私铁律。
2. **每张卡二维码/条码字段**（G3）：新增 `qrcode` 字段类型绑定名单列，命中准考证核验、签到扫码；仓库已有 qrcode 工具（R364 代码核实 utils/qrcode.ts），低风险高感知。
3. **「不同桌」硬约束开关 + 考务隔位**（G1）：自动分配时保证拆开并给出违反报告；中文考务侧无人做。
4. **折叠结构扩展**（G2）：三折底座/双脚支撑 + 粘贴边参数 + 正反面独立字段 + 背面手写留白模板细节。
5. **先试打引导**（G15）：导出/打印流程加「先打一页校准」提示与实测量尺说明——极小改动，直击教程区反复出现的翻车点。
6. **宾客自助查座的合规变体**（G12）：不做上云服务；可做 ①随排座图 hash 链接附「姓名速查」只读页（数据在链接里，打开者自查），②打印件上加「按姓氏字母速查表」（wedgenerator Find-Your-Seat sign 同型）。若未来要做真扫码查座，需单独与老板确认隐私边界。
7. **Google 表格/在线表格导入**（G4）：补第三数据源（注意 placecard.us 的「临时中转」话术表明该路径必然出域——需在 UI 明示）。
8. **餐食/特殊需求列透传**（G8）：名单列→卡面字段 + 按列筛选打印（素食/儿童餐单独出）。
9. **撤销/重做与编辑历史**（G13）：排座编辑器补齐多步 undo/redo，把 SeatLogic 的卖点变成及格线。
10. **场地底图导入**（G14）：宴会视图允许导入平面图照片做衬底摆桌。
11. **成品纸规格库**（G16）：Avery 5302/6 格卡纸/常见三角桌牌成品尺寸预设。
12. **场景 SEO 页密度对齐**（G11）：按 SCG 模式继续铺「一场景一工具页」。
13. **定价叙事**：本轮锚点更新——SeatLogic $399.99/年、PTP $299.95、Canva ¥168–499/年、创客贴 ¥159/年/人起；SeatMark 限时 0 折免费 + 免登录离线仍是最强对比位。

## 五、明确不追的方向（与铁律冲突）

- 名单上云的扫码查座/签到服务（云会助、趣座位模式）——违反零上传铁律。
- 实时多人协作（seatplan.io/SeatLogic Pro）——需服务器，无后端前提下不可行；hash 快照是替代答案。
- 微信生态接入（查座小程序/公众号）——公司规则不做微信登录。
- 真实支付——定价叙事保持现状。
