## 三、用户真实讨论 → 未满足需求（全部【二手】引述，未见 SeatMark 已覆盖项另注）

1. 「不能坐一起」是排座第一痛点：婚俗文章（hunzha.com）与 SeatLogic/lans.cloud 文案均把「谁不能跟谁同桌/同排」列为核心场景；教师场景还要「前排固定」「考试隔位」。→ SeatMark 有 /seating、/banquet 视图但未见规则约束排座能力（待代码核实）。
2. 名单最后一刻变更是常态：「婚礼前一周定稿，临时来的进备用桌」「别为临时变动打乱全表」→ 增量改名单 + 局部重排 + 防二次改乱的机会。
3. 线下交付是一套物料不是一张卡：迎宾区座位总览 KT 板 + 每桌桌号牌 + 每人席位卡 + 引导人——「三件套」跨品类组合。SeatMark 模板库已覆盖桌牌+门贴，但「一套名单 → 一次导出场布全套物料（总览图+桌号+席卡+桌贴）」的组合导出是空白。
4. 婚礼排座工具被吐槽「固定桌型、模板死板、不匹配真实场地、动辄 $200」（seatplan.io 作者在 HN 原话）→ 桌面任意桌型+自定义尺寸正是 SeatMark 毫米级设计器的长项，但排座侧是否支持自由桌型/场地底图待核。
5. 考务场景用户仍在靠 VBA/邮件合并手工流：827 下载的论坛模板 + 多篇 WPS 邮件合并教程 = 稳定搜索需求；痛点是多步骤、无预览网格、双面翻转手工、易错。
6. 教师细分需求：随机排座但须尊重「分开/同桌对」「视力/听力前排」「考试空位」——约束式随机排座在海外免费工具里已成标配，中文考务侧几乎无人做。
7. 隐私顾虑真实存在且被竞品当作卖点：yikeaigc 也强调「浏览器执行模式…可断网使用」（但离线需登录，留了小辫子）；placecard.us 强调名单留在本地。→ SeatMark 的零上传叙事仍是最彻底的，且无需登录即可离线——可继续放大。

## 五、机会点（投入小/差异大排序）

1. **「不能坐一起」升级为硬约束 + 考务隔位**：现有「不同桌」软提醒之上加硬约束开关（自动分配保证拆开、违反即红标报告），SeatingView 加隔位/空桌间隔选项。海外 5 个工具已验证刚需，中文侧无人做。【G1】
2. **每张卡二维码/条码字段**：新增 `qrcode`/`barcode` 字段类型绑定名单列（{姓名}{座位号}{单位}），命中准考证核验、签到扫码、货架取餐码。编解码器已有（utils/qrcode.ts），低风险高感知。【G3】
3. **折叠结构扩展**：三折底座/四折锁底/双脚支撑 + 粘贴边/底座深度参数 + 正反面独立字段——一可已验证需求且其离线需登录是弱点。【G2】
4. **排座 hash 分享链接**：沿用模板 hash 思路做「只读排座图链接」，无后端让婚庆/场地看最新版，绕开协作要服务器的硬约束。【G7】
5. **一套名单→场布全套导出**：总览座位图（A3 横）+ 桌号牌 + 席位卡 + 桌贴一次打包——婚礼「三件套」/会务执行单，复用模板引擎与 zip 管线。【用户讨论#3】
6. **Google Sheets/在线表格导入**：补第三数据源。【G4】
7. **餐食/特殊需求列透传**：名单列 → 席位卡字段 + 按列筛打印（素食/儿童餐单独出）。【G8】
8. **考务一键三出**：座位表+门贴+桌签同名单一次导出，正面替代 VBA 论坛模板（827 下载真实需求）。【用户讨论#5】
9. **场景 SEO 页密度对齐**：按 SCG 模式把婚礼/年会/教室/U 形/长桌/课桌各做独立场景工具页。【G11】
10. **定价叙事量化**：竞品要么免费但浅（SCG）、要么 $20–300（PTP/TTP）、要么登录+订阅（创客贴 ¥159/年/人起、Canva ¥300/年）；SeatMark ¥19 + 限免 + 免登录离线——对比页直接列价目锚点。
