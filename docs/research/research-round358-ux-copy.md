## 二、三条用户任务流实证

### 流程一：班主任排考场（/seating → /studio）

完整链路实测通过：
- 粘贴「姓名\t性别\t班级」40 行（含表头）→「已输入 40 名学生 / 48 座」+「已跳过表头行」「识别到性别列」提示，首行含「班级」列被正确判为附属列忽略；
- 「男女混排」一键排出相邻男女交替（导出 CSV 验证 排/列/座位号/姓名/性别 五列正确）；空座显示「—」（曾误判 48 非空，实为 8 个空位占位符，非缺陷）；
- 点选两座互换即时生效；「打印座位表（A4 横向）」调起 window.print，printToPDF 得 A4 横版 1 页（841.92×594.96pt）；
- 「导出座位清单 .csv」直接下载；
- 「一键生成对应桌贴」→ /studio?from=seating，名单含座位号/排/列落地 40 条，自动打开桌贴场景。

**新卡点（本轮新增）：**
1. **【推断·P2】/seating 单考场单图，无多考场拆分。** 年级统考动辄 10+ 考场：整年级名单粘贴进来只会塞满一个 6×8 网格并「超出 N 人排不下」；想按考场每人一图只能手工先把名单切成每考场一份、逐考场重复操作。桌贴链路（/studio 按考场列）已支持多考场，座位表链路没有。建议：名单含「考场」列时提供「按考场拆分为 N 张座位表」，或至少支持考场列筛选导出。
2. **【推断·P3】无「按列填充」。** 填充顺序仅「按行填充 / S 形蛇形」两种，不少学校座位号按列（一列到底再下一列）编号；目前只能靠手工逐个换座凑列序。成本=多一个 fillOrder 分支 + 选项。
3. **【实证·P4】移动端底部三件套拥挤。** /en/seating 390px 底部同时存在：下一步条（全宽 49px）、「View seating preview ↓」浮钮（120×44）、Feedback FAB（40×40），三者同层堆在 bottom-0~795px 区间，初始态即盖住名单 textarea 下缘与若干按钮；与遗留的「FAB 压座位图」属同一族问题，建议统一收口（预览浮钮并入下一步条，或 FAB 让位）。

### 流程二：婚礼策划排桌（/banquet → /studio）

完整链路实测通过：
- 「姓名\t分组」58 行粘贴 →「已导入 58 位宾客 + 新建 5 个分组」，Tab 两列正确归组；
- 「一键自动分配（同组同桌）」→ 58 人全部落座、空桌 2；14 人组 > 10 座桌时拆分明细逐条列出（「男方亲友 14 人 > 任一桌最大 10 座 → 拆到 1号桌（10 人）、2号桌（4 人）· 无桌可整组容纳」），并提供「换用『优先坐满』重新分配」备选策略——信息透明，文案务实；
- 导出前检查弹窗如实列出空桌并给「删除空桌后导出 / 跳过空桌继续导出」两选项；
- 带水印 PNG 导出 → 婚宴座位表.png（A4 横版 3509×2481，墨迹分布正常，未复现 r312 首导出平铺左缘异常）；
- 「宾客速查表」= 浏览器打印通道（非下载）：window.print 调起、printToPDF 得 A4 纵向 2 页，前半「姓名索引（拼音序）→ 桌号」+ 后半按桌名单；
- 「按桌名单 .csv」下载正确（桌名/座次/姓名/分组）；
- 「一键生成席位卡 / 桌号牌」→ /studio?from=banquet，30 条带桌号/分组/座位号落地并自动打开「婚礼席位卡」模板。

**新需求候选（前两轮已记仍缺，本轮再次确认）：**
4. **【推断·P2】人无粒度的「必同桌 / 不同桌 / 指定席位」。** 现有：组→桌指定（拆分明细里「可指定整组到某桌」）、锁桌、事后拖拽。婚宴刚需仍在缺口：新人/双方父母指定主桌席位、离异父母或矛盾亲属强制不同桌、重要客人指定离舞台近的桌。建议先做「指定某人到某桌」（拖放已有，加「钉住不动」即满足大半）；「A 与 B 不同桌」可做分配时的两两排斥清单。
5. **【实证·P4】粘贴入口发现性弱。** 「粘贴名单」只是提示文案的一部分（「还没有宾客：粘贴名单、上传 TXT…」），真正的入口是下方常显 textarea +「添加到名单（自动去重）」；首次到访视觉上 textarea 与「+ 加一行」并列，导入路径不如 /seating 的居中大粘贴框直白。建议空态下把 textarea 提为显式「粘贴名单」主操作。

### 流程三：行政做会议桌牌（/ → /studio）

完整链路实测通过：
- 首页「开始生成标签」→ /studio 默认考场模板；「浏览全部 225 款模板」对话框内搜索「会议」即刻过滤，「会议大桌牌」（190×130mm，2 枚/页）一键选用；
- 上传 12 行 xlsx（姓名/部门/职务）→「已自动匹配 2/2 个字段」，预览正确渲染（部门题头 + 特大姓名 + WELCOME 双语衬线）；
- 「图片 PNG」→ 对话框三通道说明（矢量 PDF / 图片版 PDF / PNG 各自用途一句话讲清）→「带水印导出（不限次数）」→ 下载 zip 含 12 张 2245×1536@300dpi PNG；授权服务 503 期间页面明确显示「账号服务维护中，带水印导出不限次」，fail-closed 提示得体。

**新卡点：**
6. **【推断·P3】多余的 Excel 列静默丢弃。** 12 行名单含「职务」列，模板只用 2 个字段，界面只报「已自动匹配 2/2 个字段」，没有「职务列未被使用」的提示。行政用户容易误以为职务没上牌是 bug，或反过来以为职务已上牌而漏检。建议映射面板补一行「未使用列：职务」（与「未映射字段」提示对偶）。
7. **【实证·P4】「打印校准」藏在预览工具栏次级位置。** 打印校准向导（≤0.35mm 补偿）是差异化卖点，但入口是工具栏小字按钮；首次打印跑偏的用户大概率找不到。可在首次点「打印 / 矢量 PDF」时以一次性提示引出（非弹窗打断）。

## 三、去 AI 味专项复核（本轮深挖面：全量模式扫描 + 统计复用 + 英式/美式拼写）

三道禁词护栏（bannedCopy / guideDescriptionQuality / sampleNamesRealistic）仍有效，常规营销腔 0 命中。**新扫描结论：站内中文文案系统性干净**，以下为残留小项：

1. **【代码·P4】英文 locale 英式/美式拼写混用**：centred×11 vs centered×1、colour×13 vs color×11、labelled×7 vs labeled×0、grey×3 vs gray×4，而 organization/-ization 全用美式（17:0）。同一套 UI 里「colour bar」与「organization」并存。建议统一为美式（或英式），一次机械替换。
2. **【代码·P4】模板详情描述固定尾巴**：188 条 description 以「…免费批量生成。」收尾（templateDetails*.ts），逐条前文具体、尾巴雷同——搜索结果页/分享卡片里像模板拼接。建议把「免费批量生成」收口到详情页统一位置（如 meta 或卡片角标），description 只保留场景描述；或至少变化 3–4 种收尾。
3. **【代码·P4】guide quickStart note 公式化**：「先看成品效果，再换成自己的名单；免费、无需注册，名单不出浏览器」在 guides.ts 重复 ~50 次，逐篇不换字。虽是功能性 CTA，连读多篇会显机器感。可保留结构、按场景微调配词（考务篇「换成你班名单」、婚宴篇「换成你的宾客名单」）。
4. **【代码·P4】两处「利器」、一处「大幅提升」**：`defaultTemplatesEvent.ts:394`「破冰社交利器」、`templateDetailsRound2.ts:1145`「社交破冰利器」、`guidesRound2.ts:728`「验收效率大幅提升」——个别营销腔漏网，建议「利器」→「社交破冰很顺手」之类白描，「大幅提升」→「抽查即可，不必逐人核对」（前文已有同义白描，直接删尾巴即可）。
5. **【实证】英文模板描述整体拟人度高**：enStudioDescriptions 抽查 20+ 条均为具体短句（"Peel, stick, mingle." / "Tear a corner to validate — no system needed."），无 seamless/elevate/delve 等 AI 高频词（扫描 0 命中）。
6. **【实证】教程正文与 FAQ 仍是人话**：抽样 guidesRound7 婚宴两篇（「婚礼前两天名单还在变怎么办？这是常态。」式 FAQ、如无扫码查座如实写「暂无」）、desk-card-generator FAQ（「名单只在本机浏览器里解析」等具体承诺）、/vs 页（含「两者持平」与调研日期落款），均无空洞套话、无排比堆砌。
